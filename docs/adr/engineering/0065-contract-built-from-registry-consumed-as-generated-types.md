# 0065. The contract document is built explicitly from the registry, and the browser consumes it as generated types and a hand-written fetch

**Status:** Accepted ·
**Pillar:** [Unsafe states are unconstructable, not merely untaken](../../../DESIGN.md#unsafe-states-are-unconstructable-not-merely-untaken) ·
**Serves:** [O4](../../../USE_CASES.md#o4--the-operator-can-see-and-steer)

## Context

[ADR-0042](./0042-implementation-stack.md) requires the browser's types to be generated from the
read API's contract with drift failing the build, and
[ADR-0057](../operability/0057-one-dataset-endpoint-behind-a-registry.md) makes the dataset registry
and the list of bespoke handlers the two sources that feed one contract generator, so a route
outside both fails the build. [docs/UI.md](../../UI.md#17-the-read-api) fixes the document's home
and the direction, Go code to document to browser types, and left the tools to the builder. The
tools are independently reversible from the framework of
[ADR-0063](./0063-browser-app-is-preact-with-signals.md), so they are their own record. They were
researched on 2026-09-10 and the operator accepted this decision the same day.

## Decision

- **The Go side emits the OpenAPI 3 document by populating an OpenAPI document library's typed
  structs explicitly from the registry and the handler list.** The library is `kin-openapi`'s
  `openapi3` package, used for its correct document types and serialization and for nothing
  else. Its reflection-based schema generator is not used, because the registry already declares
  every dimension, type, and closed value set and there is nothing to infer. The document is
  checked in at `ui/contract/` and regenerated in CI.
- **The browser's types are generated by `openapi-typescript`, types only, with zero runtime
  output.** Closed value sets become literal unions, not enumerations, so exhaustive switches
  carry the unhandled-value rule of [docs/UI.md](../../UI.md#7-the-rows-and-the-charts), and
  nullable fields become unions with `null`, which the `null` group key of the dataset endpoint
  needs. The generated files live under `ui/browser/src/generated/` and are never edited.
- **The dataset descriptor table the browser's URL grammar reads is generated from the same
  document**, so a dataset's defaults, groupable dimensions, filters, and sortable columns reach
  the browser without a hand edit, and the drift rule covers them.
- **The fetch is hand-written, a few dozen lines, typed by the generated types.** No client
  generator. The generated types' own maintainers direct users the same way for their fetch
  companion, which they placed in maintenance.
- **The drift check is regenerate and diff, three times.** The document from the registry, the
  types from the document, the descriptor table from the document, each compared to what is
  checked in, and any difference fails CI. It is a reproducibility check and is recorded as one.
  It proves the checked-in artifacts equal what today's generator produces, never that the
  generator is right, and never that the served response matches the document. The Go
  integration tests against the real handlers carry those two claims.

The pipeline, stage by stage:

| Stage | Tool | What the drift check compares |
| --- | --- | --- |
| The OpenAPI document | own code populating `kin-openapi`'s document structs from the registry and the handler list | the checked-in document to a fresh generation |
| The browser's types | `openapi-typescript`, types only | the checked-in types to a fresh generation from the document |
| The dataset descriptor table | own generator over the document | the checked-in table to a fresh generation from the document |
| The fetch | hand-written, typed by the generated types | nothing, it is source |

## Alternatives considered

- **A reflection-based Go generator that infers schemas from request and response types.** Its
  case was less code per endpoint. Rejected because the registry already declares everything a
  schema needs, so reflection would add tag conventions and inference corner cases on nullable
  fields and closed value sets to fight rather than use.
- **A hand-written struct set for the document.** Its case was no dependency at all. Kept as the
  fallback if the library's types prove awkward to populate, and not chosen first because the
  library already has the document's serialization edge cases right.
- **The generated types' fetch companion.** Its case was a typed fetch for free. Rejected because
  its maintainers placed it in maintenance and recommend a local fetch instead.
- **Client generators that emit an SDK by default.** Their case was more generated, less written.
  Rejected because they generate runtime code the design does not need, with larger and
  faster-moving dependency trees, to reach the same types.

## Consequences

- Adding a dataset or a bespoke endpoint is one registry entry or one handler and a regeneration.
  Nothing on the browser side is written by hand for it except a row renderer.
- Two things the check does not catch are named so a green run is not over-read. A deterministic
  generator bug passes every time, and a registry change that serializes identically passes
  silently. Both are the Go tests' business.
- Assumptions about other components: every registry entry declares its row type explicitly with
  closed value sets (ADR-0057). The generator tool runs under bun, which the spike of ADR-0063
  exercised. The fixtures of [ADR-0064](./0064-browser-tests-run-under-bun-against-a-dom-shim.md)
  are typed by these generated types, which is what makes them contract-checked.
- The drift check is a control. Its violation injection is catalogued in
  [docs/VERIFICATIONS.md](../../VERIFICATIONS.md).
