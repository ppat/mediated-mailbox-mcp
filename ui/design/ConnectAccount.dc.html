step 1 asks the mailbox first and proposes the identifier. confirming it starts the attempt, so it refuses here an identifier that is ., .. or /, one the UI's own top-level paths use (setup, api, main.js, main.css…), or one already taken. step 2's button is then a plain link, so no pop-up blocker stops it
one attempt per browser session, held by the server across replicas. a reload restores identifier, mailbox and countdown. focus returns to the paste field when this tab is visible again, and Enter connects
re-authorize is this page at /personal/account/reauthorize: step 1 is a read-only summary (identifier, provider, the client it connects through, the remembered mailbox), and steps 2 and 3 are the same. success replaces the stored credential.

moving: while Gmail has another client, the summary carries "Connect through another client", which opens the list without the account's current client and sets client=. step 3's button then reads "Move personal to acme-mailbox", and success "Moved personal to acme-mailbox." the new client and credential are written together. a failed move leaves the old ones.
