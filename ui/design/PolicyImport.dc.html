export and import, one scope at a time
Import and Export on personal's policy screen act on personal's own rules alone. Export downloads policy-personal.yaml as stored, asks nothing, changes nothing. the file is checked whole before anything shows. the preview is the difference, lifted and removed first in the restricted color, each with personal's numbers, the senders and stored messages no other rule restricts.
other states
· nothing lifted: the button reads "Import {n} changes" and applies at once, since it only adds restriction.
· the file matches: "The file matches the stored rules. Nothing to import." no button.
· a refused file: refused whole, each problem with its rule and line, such as a file that is not this form, a suffix not shaped like a domain name, two rules sharing an identifier, or a file over 1 MB.
· any scope: a file names no scope, so one exported from the base policy or from any account, work's included, imports here, and personal's file imports as the base policy or into any other account. identifiers are unique within a scope only, so a file never collides with another scope's rules.
· stale: "The policy changed since this preview. Preview again."
· after: the browser returns to the policy screen, which reads "Imported: 2 rules added, 1 rule edited, 2 restrictions lifted." and "Put back the 2 lifted restrictions", which adds back exactly what the import lifted, with no confirmation.
the base variant, /setup/policy/import
the same screen in the installation frame, titled "Import the base policy" with "The file replaces the base rules, which every account inherits." lifted rules and removed suffixes carry no counts. the dialog lists each lift, states "Every account loses these restrictions: family, personal, work." and the same released and recall sentences, and asks for lift {k} typed before its button enables, reading "Type lift {k} to enable" while disabled. an account's import, as drawn above, needs no typing.
